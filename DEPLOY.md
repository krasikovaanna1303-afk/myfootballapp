# Публичный сайт «Касание»

Приложение уже является веб-сайтом. Чтобы открыть его с телефона или другого компьютера, нужен хостинг, который запустит Node.js-сервер и выдаст внешний HTTPS-адрес. Одного размещения папки `dist` на статическом хостинге недостаточно: регистрация, игры, отзывы и каталог используют API и SQLite.

## Пробный запуск на Render

В проект добавлены `Dockerfile` и `render.yaml`. Развёртывание настроено на ветку `codex/kasanie-web`. Сервис Render и публичный адрес создаются отдельно в аккаунте хостинга.

После загрузки кода в GitHub:

1. В Render войдите в свой аккаунт и создайте **Blueprint**, выбрав репозиторий `krasikovaanna1303-afk/myfootballapp` и нужную ветку. Файл `render.yaml` указывает `codex/kasanie-web`; выберите эту ветку в мастере Blueprint.
2. Проверьте, что выбраны сервис `kasanie-football` и бесплатный тариф `free`. Развёртывание выполняется из `Dockerfile`; адрес появляется в панели Render после успешного запуска.
3. Откройте выданный HTTPS-адрес. `/api/health` должен возвращать `ok: true`; на главной странице должны появиться площадки. Создайте аккаунт, свою игру и проверьте присоединение из другого браузера.

Бесплатный сервис подходит для знакомства с интерфейсом: он засыпает при простое, первый запрос может быть медленным, а **SQLite теряется при перезапуске / повторном развёртывании**. Не используйте такой запуск для хранения настоящих пользовательских данных. Постоянный диск Render требует другого тарифа; платные ресурсы этим проектом не создаются автоматически.

Для постоянной базы на Render потребуется подключить persistent disk к `/app/data` и оставить `DATABASE_PATH=/app/data/kasanie.sqlite`. Выбор платного тарифа и диска делайте только осознанно в настройках хостинга. Альтернатива — собственный сервер с Docker и постоянным томом.

## Собственный сервер

Нужны Docker Compose, внешний адрес сервера и настроенный HTTPS-прокси. Из корня проекта:

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 web
```

Контейнер слушает порт `3000`; `WEB_PORT` позволяет изменить внешний порт. Именованный том `kasanie-data` сохраняет базу между обновлениями контейнера. **Не запускайте `docker compose down -v`: это удалит данные.**

Направьте домен через существующий HTTPS reverse proxy на порт приложения. Сервер доверяет одному прокси; с HTTPS-соединением cookie сессии получает флаг Secure. Если используется другой proxy chain, проверьте конфигурацию `trust proxy`.

## Доступ и проверка

Для подготовки контейнера ключи не требуются. Для публикации нужен доступ к выбранному хостингу и, при автоматическом развёртывании из GitHub, возможность загрузить текущий код в репозиторий. Пароли и API-ключи не отправляйте в чат: используйте защищённые настройки среды / хостинга.

Сайт использует демо-каталог, а не полный проверенный перечень футбольных полей. Секреты, `.env`, локальная база и зависимости исключены из Docker build context и архива исходников.
