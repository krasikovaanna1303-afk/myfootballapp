# ПОЛЕ: включение настоящих фоновых push-уведомлений

Файлы приложения уже готовы. Ни VAPID private key, ни service-role key нельзя добавлять в GitHub Pages или отправлять в чат.

## 1. Таблица устройств

В Supabase → **SQL Editor** выполни целиком [`background-web-push.sql`](background-web-push.sql).
Это дополнение к ранее выполненному `notifications-and-inbox.sql`; повторное выполнение не удаляет данные.

## 2. Сгенерируй два секрета

Открой **https://krasikovaanna1303-afk.github.io/myfootballapp/tools/push-setup.html**.

Нажми «Сгенерировать VAPID-ключи» и скопируй весь JSON. Затем сгенерируй секрет webhook.

В Supabase → **Edge Functions → Secrets** добавь:

| Имя | Значение |
| --- | --- |
| `POLE_VAPID_JWKS` | Весь JSON из генератора |
| `POLE_WEBHOOK_SECRET` | Строка из генератора секрета webhook |

Не публикуй значения. После настройки не генерируй новый VAPID-ключ без необходимости: старые подписки браузеров после смены ключа придётся создавать заново.

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` предоставляет среда Supabase Edge Functions автоматически; они не должны попадать в исходники сайта.

## 3. Разверни Edge Function

В **Edge Functions** создай функцию с именем **`pole-web-push`**. Содержимое — [`functions/pole-web-push/index.ts`](functions/pole-web-push/index.ts).

В настройках **Verify JWT** для этой функции должно быть **выключено**: запросы идут от Database Webhook и GET для публичного VAPID-ключа. POST при этом защищён отдельным `x-pole-webhook-secret`, который проверяет функция.

Через CLI (если используешь его) это выглядит так:

```bash
supabase login
supabase link --project-ref ID_ТВОЕГО_ПРОЕКТА
supabase functions deploy pole-web-push --no-verify-jwt
```

Проверка: GET-запрос к `https://ID_ПРОЕКТА.supabase.co/functions/v1/pole-web-push` возвращает JSON с `publicKey`, без приватных ключей. До задания секретов функция ответит ошибкой конфигурации.

## 4. Подключи Database Webhook

Supabase → **Database → Webhooks → Create**:

- Название: `pole_notify_web_push`.
- Событие: **INSERT**.
- Схема: `public`, таблица: `pole_notifications`.
- Отправка: **Supabase Edge Functions** → `pole-web-push`, метод **POST**.
- Заголовок: `x-pole-webhook-secret`, значение **точно такое же**, как `POLE_WEBHOOK_SECRET`.
- `Content-Type: application/json`.

Другие события (`UPDATE`/`DELETE`) отмечать не нужно. Webhook срабатывает на автоматически созданные уведомления.

## 5. Включи подписку в приложении

1. Открой ПОЛЕ по HTTPS и войди в аккаунт.
2. Перейди в 🔔 **Уведомления** → **Включить фоновые push**.
3. Разреши браузеру показывать уведомления.
4. Для проверки: на втором аккаунте запишись на игру первого или напиши ему. Первый аккаунт должен получить уведомление даже при закрытой вкладке.

На iPhone/iPad (iOS/iPadOS 16.4+) сначала нужно добавить ПОЛЕ на **экран «Домой»** и запускать оттуда. Разрешение выдаётся после нажатия на кнопку подписки.

## Безопасность и диагностика

- Подписки доступны через RLS только их владельцу, смена владельца устройства осуществляется через защищённую SQL-функцию.
- При выходе из аккаунта браузер отписывается, чтобы личные push не продолжали приходить следующему пользователю устройства.
- При ответе push-сервера `404/410` устаревшая подписка удаляется автоматически.
- Секрет webhook проверяется перед обращением к базе; private VAPID-ключ не отправляется браузеру.
- Web Push сервер отправляет только заголовок и краткое описание события, не полный текст личного сообщения.
- Подписки поддерживаются в Chrome/Edge (FCM), Firefox (Mozilla Push), Safari (Apple Push) и WNS. Для иных push-сервисов серверный список разрешённых доменов понадобится дополнить.
- Если уведомление не пришло, проверь **Edge Functions → Logs**, историю **Database Webhooks**, разрешения уведомлений на устройстве и состояние браузерной подписки.

## Почему не Firebase?

Приложение — веб-сайт, а не нативное мобильное приложение. Для него достаточно открытого стандарта Web Push: Service Worker + VAPID + Supabase. Отдельный Firebase-проект не требуется.
